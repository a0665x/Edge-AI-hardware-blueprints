Application scenarios

Choose a nearby scenario and inspect its constraints.

Camera and distance→Timing→Output quality

Explore by scenario

People flow and line crossing

Detect people, associate IDs with MOT and count directional line crossings. Validate event recall, hourly false alerts, occlusion and crossing traffic; IDs do not establish identity. Acceptance: Line-crossing recall, false alerts/hour, occluded/crossing IDs, P95 and frame drops.

Stationary visual inspection

Capture a stopped or triggered workpiece and locate defects for review. Specify defect pixels, lighting and cycle deadline. Improve optics or tile images before buying more compute. Acceptance: Minimum defect pixels, misses/false rejects, lighting shifts, trigger-to-result and takt.

Documents and gauges

Rectify perspective, run text detection and recognition, then validate field formats. Add VLM only for open semantics or complex layout. Measure field accuracy and exception handling. Acceptance: Per-field accuracy, character pixels, glare/angle, format rejection and recapture.

Surface point tracking

Track selected texture points and occlusion on deformable surfaces. Fix causal TAPIR, point count, input size, speed and feature pixels. High camera FPS reduces inter-frame movement but is not a universal requirement. Acceptance: Point error/visibility, feature pixels, inter-frame motion, occlusion recovery, state peak and P95.

Space and distance

Estimate foreground/background relations in warehouses, drones or mobile robots. Relative depth is not metres. Metric use requires calibration, a suitable checkpoint and ground truth. Acceptance: Separate relative ordering and metric error; near/far ground truth, scale drift and reflective/transparent failures.

Video object masks

Select an object, propagate masks with SAM 2 and review failures. Live use needs memory-state, occlusion, restart and end-to-end latency measurements. Acceptance: IoU/boundary accuracy, occlusion, reprompt rate, per-clip time and memory state.

Event semantic review

A light detector selects inspection frames for VLM review. Keep fast alerts on deterministic rules. Specify structured output, abstention and error acceptance. Acceptance: Event recall, semantic errors, abstention, schema validity, burst queues and VLM P95.

Robot obstacle avoidance

Fuse metric depth and odometry for low obstacles in an AMR path. Specify near/far errors, minimum obstacle size and reflective/textureless failures. Validate AI and safety controls separately. Acceptance: Distance-band metre errors, low obstacles, stopping envelope, reflection/low texture and control failures.

Gimbal and moving-camera tracking

Separate target motion from camera rotation. A gimbal does not eliminate shake. Validate timestamps, IMU alignment, shutter readout, exposure and compensation residuals. Acceptance: Angular speed, FOV, timestamp error, compensation residuals, shutter readout and tracking recovery.

Voice agent

A maintenance assistant retrieves manuals and proposes tool actions for confirmation. Define 500 ms as first audio or completed reply; specify model, context, endpointing, noise and echo cancellation. Acceptance: WER, VAD endpoint, first-audio/full-reply P95, AEC, barge-in, long-context and concurrency peaks.

Knowledge and tool agent

Retrieve maintenance documents and return verifiable instructions. Require citations, refusal on missing evidence, tool permissions and timeouts. Indexes also consume RAM and SSD. Acceptance: Citation accuracy, retrieval recall, evidence refusal, tool permissions/timeouts, prefill/decode and index capacity.

Checkout and order verification

Compare visible tray or package items against an order. Similar packaging, reflections, overlap and unknown SKUs require explicit validation and human review. Acceptance: SKU/count accuracy, similar packaging/occlusion, unknown SKU, OCR fields and review rate.

Smart security camera

Rectify optics and run regional intrusion or person/vehicle rules. Verify low light, fisheye distortion, encoding and operating temperature; ISP integration matters. Acceptance: Day/night recall, false alerts/hour, wide-angle edges, concurrent encoding/AI and thermal steady state.

Pose and action analysis

Estimate skeletal joints and classify workstation actions. Specify joint error, occlusion, people count and window latency. Skeleton data can still be sensitive. Acceptance: Joint errors, multi-person occlusion, action-window delay, privacy and failure handling.

Drone long-range tracking

Track a distant target from a drone with a narrow FOV. Estimate target pixels from range, size and optics; measure vibration, haze, heat shimmer and tracker input cadence. Acceptance: Target/texture pixels at real ranges such as 30–120m, telephoto shake, haze/heat shimmer and reacquisition.

Drone aerial mapping

Map from aerial imagery with VIO/SLAM and GNSS or surveyed control points. Validate overlap, altitude, timestamp alignment and scale drift; relative depth alone does not provide metric mapping. Acceptance: Control-point/GNSS ground truth, scale/trajectory drift, image overlap, localization loss and map RAM.

Drone flight obstacle avoidance

Use synchronized metric sensing for low-speed indoor flight. Specify obstacle size, range error, flight velocity, control delay and emergency behavior. Planning calculations are not flight certification. Acceptance: Near/far metre errors, minimum obstacle, flight latency, stopping envelope and failure handling.

Mobile robot spatial perception

Combine obstacle sensing and localization on a moving robot. Validate changing viewpoints, low texture, reflective objects, IMU synchronization and minimum reliable sensing range. Acceptance: Near/far error, minimum obstacle, localization drift, moving-camera quality and sensor recovery.

Vehicle long-range observation

Observe distant objects from a vehicle, with detector and motion/depth paths as required. Define projected pixels, road vibration, rolling shutter and latency. This tool does not certify autonomous driving. Acceptance: Resized target pixels at ranges such as 80m, vibration, shutter/exposure, P95 and failure alerts.

AIoT: ESP32 + local LLM

An ESP32-S3 voice terminal captures audio, displays replies and controls devices through a local Qwen server on the home LAN. Qwen weights reside on the host. Budget concurrent ASR, LLM and TTS there. Separate BLE provisioning from audio transport; NX/AGX suitability depends on model, precision, context and concurrency. Acceptance: LAN round-trip P95, reconnects, first audio/full reply, concurrent host RAM, microphones and AEC.

AIoT: ESP32 camera vision

The camera node segments colors, detects changes or uses ESPDet-Pico for single-class detection and sends compact events. S3 uses DVP or bandwidth-limited USB UVC. P4 adds MIPI CSI/ISP and USB HS, with a separate wireless chip. Running YOLO11/YOLO26 does not imply 30 FPS; pin quantization, input, dataset and SDK. Acceptance: Camera driver, input pixels/classes, quantization accuracy, full-pipeline FPS, PSRAM high-water mark and frame drops.

AIoT: home companion

A small expressive display gadget accepts push-to-talk input, shows replies and controls home devices; compare Muse service with a self-hosted local backend. Muse requires app pairing and an SDK token; board features vary. Default replies are text; spoken output needs an added TTS integration. The local backend is a custom alternative, not an offline Muse deployment. Acceptance: Pairing, token, text/voice scope, data destination, offline fallback, OTA rollback and command permissions.

Algorithm selection

Fix the model and input before comparing performance.

Checkpoint→Input size→Temporal state

Explore by scenario

YOLO + object tracking

Start with YOLOv8 n/s/m at 640 and MOT such as ByteTrack. Inspect Conv, Resize, Concat, decode, NMS and INT8 calibration in the actual exported graph. Do not mix model generations or export recipes.

OCR

Detection and recognition are separate tasks. Text crop count adds work; validate viewing angle, glare, character pixels and business formats.

TAPIR / TAPNet

Fix causal checkpoint, points, size and state. Inspect correlation, sampling and temporal operations in the exported graph. GPU prototyping does not guarantee edge real time.

CoTracker

Online mode processes chunks/windows, adding waiting time. Point count, attention and state affect memory and latency. Selected model cards run together; remove TAPIR to compare alternatives.

SAM 2

Profile encoder, prompt decoder and memory attention separately. Paper results on A100 cannot be converted directly into Jetson or NPU FPS.

Motion compensation / IMU fusion

Use calibration, IMU, global motion or optical flow to estimate camera motion. Validate rolling shutter and timestamp error; compensation is not assumed perfect.

Streaming ASR + VAD

Specify language, microphone range, noise, wake word and endpointing. Measure WER and final-transcript latency.

Streaming TTS + AEC

Specify first audio delay, language, voice and stream format. Echo cancellation and barge-in require an actual audio-loop test.

RAG / tool calling

Budget embeddings, reranking, indexes and tool execution separately. LLM decode tok/s alone does not describe agent latency.

Pose / action model

Start with lightweight pose, then choose action windows against deadlines. People count, joints, viewpoints and temporal state add load.

SLAM / VIO / GNSS fusion

Specify sensor calibration, timestamps, feature quality, map storage and GNSS/control-point anchors. Validate tracking loss and recovery on the actual trajectory.

ESP32 connectivity and control

The endpoint handles provisioning, audio buffers, display and control. LLM inference belongs to the chosen local or service host. Test reconnects, API permissions, OTA and rollback.

MCU classical CV / ESP-DL

Start with grayscale, thresholds, color blobs or frame differences. Neural detection needs an ESP-DL-compatible quantized graph and separate SRAM, PSRAM and flash budgets. Custom YOLOv8n exports do not inherit Pico FPS.

Depth and decisions

Depth colors are not metres; decision models need deployment resources.

Relative / metric depth→Local / cloud decisions

Explore by scenario

Depth Anything

DAC follows the user's Depth Anything interpretation. Separate relative and metric models. Check Resize, normalization, attention and output scale against calibration data.

VLM classifier

Fix image tokens, context, quantization and reply length. Measure prefill, first token, complete reply and peak memory rather than borrowing detector FPS.

Jev / RLCD Qwen decision

In this tool Jev means the user's local RLCD + Qwen decision checkpoint. Specify parameters, quantization, runtime and state. Cloud API removes this model's local inference load; network and service latency still matter.

Stereo / ToF depth

Focal length, baseline, synchronization and sensing uncertainty determine metric accuracy. Validate both processing load and physical sensor integration.

LLM / Strata

Default to the Strata Qwen3.8-Flash-Next route: GPU expert cache, CPU/RAM experts and SSD embeddings. Desktop results are not Jetson benchmarks. Cloud deployment is available separately.

Distance-dependent error

Specify absolute error at near and far test points, plus percentile or maximum-error acceptance. The requirement is not proof a model achieves it.

Pipeline and timing

Camera FPS, model FPS and response latency differ.

Capture→Preprocess→Infer→Output

Explore by scenario

Long-range and moving-camera acquisition

Central pinhole estimate: fx=W/(2 tan(FOV/2)); target width≈fx × physical width/range. Convert camera angular speed to pixels/s and add target motion. Resized texture, exposure blur, FOV, IMU alignment and telephoto shake constrain tracking. DLSS/interpolation does not add real observations.

Camera and motion

Use actual camera FPS, image-plane speed, exposure and resized features. Frame interpolation cannot restore unobserved camera information.

FOV and target footprint

Specify horizontal FOV, sensor output, target box and resized size. Wide FOV reduces pixel density; digital enlargement adds no optical detail.

Body and gimbal vibration

Estimate central image movement from FOV and angular speed, then verify timestamps, IMU alignment and shutter readout. Measure compensation residuals.

Voice response and acoustics

Budget VAD, ASR, prefill, LLM, tools and TTS. Distinguish first audio from complete reply and include playback time when appropriate.

Long-range and telephoto imaging

Combine range, target size, FOV, exposure, haze and stabilization. Small distant targets may fail at image acquisition before compute becomes the bottleneck.

Concurrent resources

Concurrent models share memory and compute capacity.

Weights→Per-stream state→Peak memory→Latency

Explore by scenario

Concurrent model resource pool

All selected techniques run concurrently. Memory = system + shared weights + per-stream/request state. Check separate host RAM/VRAM for discrete GPUs and total memory for unified systems. Strata host uses the larger of its documented minimum and planned residence plus other host tasks. Editable GB defaults are planning envelopes, not benchmarks. Sum ms × Hz × copies /1000 only on the profiled device; missing measurements remain unknown.

AIoT: endpoint and backend budgets

Budget ESP32 PSRAM, raw buffers and audio/display in MB; evaluate Qwen, ASR and TTS on the separate host in GB. Network round trip and endpoint processing share the response deadline. Muse is not an offline model, and BLE provisioning is not a verified audio transport.

Continuous real time

Validate FPS, P95 latency, oldest frame age and drop rate together. Pipeline throughput and per-result latency are distinct.

Multiple cameras

Streams multiply decode, ISP, transfers, model state and inference work. Verify carrier CSI/USB/Ethernet interfaces, synchronization and drivers.

Physical RAM cap

Set a maximum acceptable installed-memory configuration. Available memory is smaller; loading one model does not prove concurrent, long-running operation avoids OOM.

Platforms and procurement

Reject unsuitable devices before comparing procurement bands.

Compatibility→Capacity→I/O and power→Low / Medium / High

Explore by scenario

Module procurement bands

Use only Low/Medium/High bands. These are not retail prices or dollar estimates. Defaults are illustrative; override against a consistent BOM scope, volume and supplier quotes. Hard exclusions precede technical-first or cost-first ordering. Do not compare a bare chip, SoM, carrier and finished computer as equivalent costs.

Fully offline

All required inference must deploy locally. A required cloud API conflicts with this condition. Offline batch and fully offline deployment are different requirements.

System power cap

Include compute module, carrier, cameras, storage and cooling. Module power mode is not measured system power; unknown boards remain unverified.

Sensor I/O and synchronization

Check actual carrier wiring, drivers, timestamps and sustained bandwidth. SoC capability does not guarantee a board exposes it.

PoC acceptance

Use real data and the full pipeline to verify the device.

Set targets→Test hardware→Check failures→Decide
Is the output correct?

Accuracy, misses, distance error: choose scenario-specific metrics.

Is it fast enough?

Check end-to-end P95 and drops, not just average FPS.

Can it sustain the load?

Run models together; measure peak RAM, power and thermal stability.

Pass → prototype. Fail → adjust model, camera or device and retest. Agree targets first; example numbers are not guarantees.

Align terminology before comparing capabilities.

Explore by scenario

Jev terminology and deployment correction

This tool follows the user definition: Jev is a local RLCD + Qwen decision checkpoint, not a required public service API. The product owner must provide the exact checkpoint/training implementation. Cloud is optional and removes only that model’s local inference load; ASR/TTS/vision remain. Fully offline operation cannot depend on cloud.

DAC

Depth Anything family here. Relative depth is not a metric distance.

Jev
